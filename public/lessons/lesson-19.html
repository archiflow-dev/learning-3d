1. 为什么不用任何浮点数和除法，仅靠整数加减就能画出任意斜率的直线？(Bresenham 中点判别法)

经过 Lesson 18 的透视除法与视口变换后，几何顶点落在了屏幕像素网格上。最笨的画线法（DDA）每走一列 $x$ 就要计算一次浮点斜率累加 `y += dy/dx` 并调用 `round(y)` 取整。1965 年，IBM 工程师 Jack Bresenham 问了一个极具 3Blue1Brown 几何美感的问题：

假设我们在第一卦限（$0 \le \Delta y \le \Delta x$）刚刚点亮了像素 $(x_k, y_k)$。往右走一格到 $x_k + 1$ 时，候选像素其实只有两个：**正东 East $(x_k+1, y_k)$** 或 **东北 North-East $(x_k+1, y_k+1)$**！ 怎么判断真实直线离谁更近？**只需看这两个像素正中间的“中点 $M = (x_k + 1,\; y_k + 0.5)$”位于直线的上方还是下方！**

$$F(x, y) = \Delta y \cdot (x - x_0) - \Delta x \cdot (y - y_0) = 0$$

为了消灭中点坐标里的 $0.5$ 小数，我们把中点代入隐函数并**整体乘以 $2$**，定义纯整数判别式 $d_k = 2 F(x_k + 1, y_k + 0.5)$：

$$d_0 = 2\Delta y - \Delta x, \qquad d_{k+1} = \begin{cases} d_k + 2\Delta y & (\text{若 } d_k < 0 \implies \text{选正东 East } y_{k+1}=y_k) \\[6pt] d_k + 2\Delta y - 2\Delta x & (\text{若 } d_k \ge 0 \implies \text{选东北 NE } y_{k+1}=y_k+1) \end{cases}$$

✨ 零浮点、零除法奇迹：整个循环里只有整数加法（$+2\Delta y$ 或 $+2\Delta y - 2\Delta x$）和一次符号位判断（$d_k \ge 0$），在几十年前的早期绘图仪和现代嵌入式芯片上快如闪电！

2. 现代 GPU 并行边缘函数 (Pineda Edge Functions) 与 Top-Left 共享边裁决法则

早期 CPU 用扫描线活性边表 (Scanline AET) 一行接一行地填涂多边形，但这需要维护复杂的边链表且难以大规模并行。1988 年 Juan Pineda 提出了一个彻底解放 GPU 算力的洞察： 一个逆时针 (CCW) 三角形 $\triangle V_0 V_1 V_2$，本质上就是三个有向半平面的交集！

$$E_{ij}(x, y) = (x - x_i)(y_j - y_i) - (y - y_i)(x_j - x_i)$$ $$P \in \triangle V_0 V_1 V_2 \iff E_{01}(P) \ge 0 \;\land\; E_{12}(P) \ge 0 \;\land\; E_{20}(P) \ge 0$$

因为 $E_{ij}(x, y) = A x + B y + C$ 是关于屏幕坐标的线性函数，往右走 1 个像素只需加上常数 $A = \Delta y$，往下走 1 行只需加上 $B = -\Delta x$！成千上万个 GPU 线程可以同时对包邮盒内的任意像素独立求值！

棘手的边界死局：如果一个像素中心恰好踩在两个相邻三角形的公共边上 ($E_{ij}(P) = 0$)，它到底归谁？

  • 若两边都按 $E \ge 0$ 录取：公共边上的像素被重复绘制 2 次 (Double Overdraw)，半透明玻璃会留下一道刺眼的亮缝！
  • 若两边都按 $E > 0$ 严格录取：公共边上的像素两边都不管，模型接缝处直接漏出背景黑洞（漏点裂缝 Cracks）！
  • GPU 黄金标准——Top-Left 填充规则：规定压线像素（$E=0$）仅当该有向边是三角形的 上边 (Top Edge，水平且朝左) 或 左边 (Left Edge，严格朝下倾斜) 时才予以点亮！因为相邻两个逆时针三角形经过同一条公共边时的行进方向必定相反（一个朝下 Left，另一个必定朝上 Right），从而保证不重不漏、100% 互斥划分！

⚠️ 为什么不能直接用屏幕 2D 重心坐标线性插值纹理 $(u, v)$？

初代 PlayStation (PS1) 游戏里的地面纹理之所以会沿着对角线接缝剧烈扭曲跳动，正是因为它直接用屏幕二维重心坐标 $(\alpha_{\text{2D}}, \beta_{\text{2D}}, \gamma_{\text{2D}})$ 做了仿射插值！ 由于透视除法除以了非线性深度 $w_c = -z_e$，三维空间中均匀变化的属性 $u$ 在屏幕二维空间中并不是线性的，而是$u / w_c$ 和 $1 / w_c$ 在屏幕二维空间中呈严格线性！

$$u_{\text{correct}}(P) = \frac{\alpha_{\text{2D}} \frac{u_0}{w_0} + \beta_{\text{2D}} \frac{u_1}{w_1} + \gamma_{\text{2D}} \frac{u_2}{w_2}}{\alpha_{\text{2D}} \frac{1}{w_0} + \beta_{\text{2D}} \frac{1}{w_1} + \gamma_{\text{2D}} \frac{1}{w_2}}$$
💻 GPU 边缘函数 + Top-Left 规则核心实现
// Pineda 有向边函数与 Top-Left 判定偏置
bool isTopOrLeftEdge(Vec2i v0, Vec2i v1) {
  Vec2i e = v1 - v0;
  bool isTop = (e.y == 0 && e.x < 0); // 水平朝左
  bool isLeft = (e.y < 0);            // 严格朝下 (Y轴向上坐标系)
  return isTop || isLeft;
}

int edgeFunc(Vec2i a, Vec2i b, Vec2i p) {
  return (p.x - a.x) * (b.y - a.y) - (p.y - a.y) * (b.x - a.x);
}

// 若不是 Top-Left 边，初始偏置设为 -1，使 E >= 0 等价于 E > 0
int bias01 = isTopOrLeftEdge(v0, v1) ? 0 : -1;
int bias12 = isTopOrLeftEdge(v1, v2) ? 0 : -1;
int bias20 = isTopOrLeftEdge(v2, v0) ? 0 : -1;

if ((E01 + bias01 | E12 + bias12 | E20 + bias20) >= 0) {
  shadeFragment(px, py); // 符号位全为正，点亮像素！
}
