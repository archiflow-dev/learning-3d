1. 为什么“先画远处、后画近处”的画家算法在数学上必然失败？(循环遮挡悖论 vs. 逐像素 Z-Buffer)

为了解决三维场景中的遮挡关系（Hidden Surface Removal），最符合人类直觉的想法是 画家算法 (Painter's Algorithm)：就像油画家先画远处的天空和群山，再把近处的树木画上去覆盖背景一样，我们把所有三角形按深度从远到近排序（Back-to-Front），依次涂到屏幕上！

3Blue1Brown 数学批判：一个集合能够被排序的前提是，它上面的比较关系必须是一个满足传递性 (Transitivity) 的偏序关系 (Partial Order)！ 然而在三维空间中，“多边形 $A$ 遮挡多边形 $B$”这个二元关系根本不满足传递性！

$$\text{Red } A \prec \text{Green } B, \quad \text{Green } B \prec \text{Blue } C, \quad \text{但 Blue } C \prec \text{Red } A \;\;(\text{剪刀石头布死循环！})$$

如右侧实验台所示：三个互不相交的长条三角形像风车叶片一样互相压住对方的一端。无论你尝试全部 $3! = 6$ 种绘制顺序中的哪一种，永远至少有一处交叠区的遮挡关系是画反的！

1974 年，皮克斯创始人 Ed Catmull 提出了一个降维打击的哲学突破——Z-Buffer（深度缓冲）： 不要再去给“整个三维三角形”排序了！把排序的粒度拆碎到“每一个二维像素 $(x, y)$”上！ 虽然整片三角形之间会形成剪刀石头布的循环遮挡，但在穿过单个像素 $(x, y)$ 的同一条一维视线上，三个深度实数 $z_A(x,y), z_B(x,y), z_C(x,y) \in \mathbb{R}$ 永远具有严格的全序关系！每个像素只需独立记录当前见过的最小深度 `zBuffer[x][y]`：

$$\text{if }\big(z_{\text{frag}}(x, y) < \text{zBuffer}[x][y]\big)\; \big\{\; \text{zBuffer}[x][y] \leftarrow z_{\text{frag}};\;\; \text{color}[x][y] \leftarrow C_{\text{frag}}; \;\big\}$$

✨ 结论：Z-Buffer 彻底解放了三角形的提交顺序——无论你按什么顺序把三角形丢给 GPU，逐像素深度测试都能自动解开任意复杂的循环遮挡和互相穿插！

2. 如果没有硬件 Z-Buffer 怎么办？——《DOOM (1993)》背后的 BSP 二叉空间分割树

在 1993 年 3D 加速卡尚未诞生时，内存极其昂贵，根本塞不下全屏 Z-Buffer。John Carmack 是如何让《DOOM》在 486 CPU 上以丝滑帧率渲染出复杂迷宫且绝不发生遮挡错乱的？答案是 **Fuchs 等人 (1980) 提出的 BSP 树 (Binary Space Partitioning Tree)**！

  1. 离线递归切分 (Offline Split)：任选一面墙所在平面 $H_0: \mathbf{n}_0 \cdot \mathbf{x} + d_0 = 0$ 作为根节点，将空间一分为二：正半空间 $H_0^+$ 与负半空间 $H_0^-$。若有任何其他墙面横跨切分平面 $H_0$，直接在交线处把它锯成两半（从而彻底斩断所有循环遮挡环！）。
  2. 运行时视角自适应中序遍历 (Runtime $O(N)$ Traversal)：无论玩家相机 $\mathbf{E}$ 走到哪里，只需把相机坐标代入节点平面方程 $s = \mathbf{n} \cdot \mathbf{E} + d$：
    • 若相机在正侧 ($s > 0$)：先递归画负子树 $H^-$（远侧） $\to$ 再画当前根节点墙面 $\to$ 最后递归画正子树 $H^+$（相机同侧）！
    • 若相机在负侧 ($s < 0$)：顺序完全反转（先画 $H^+$ $\to$ 根节点 $\to$ $H^-$）！

⚠️ 哪三种操作会当场废掉 GPU 硬件的 Early-Z 深度早测优化？

现代 GPU 默认在光栅化之后、执行 Fragment Shader 之前进行 `Early-Z` 测试。但如果你的 Shader 触犯了以下三条禁忌，硬件被迫退回 `Late-Z`（必须先跑完昂贵的 Shader 才能测深度）：

  1. 在 Fragment Shader 中改写深度 (gl_FragDepth = ...)：因为跑完 Shader 前根本不知道最终深度是多少！（除非使用 `layout(depth_greater) out float gl_FragDepth;` 保守深度声明）。
  2. 使用 discard 或 Alpha Test 镂空丢弃片元：如果提前在 Early-Z 阶段把该镂空片元的深度写进了 Z-Buffer，而后面 Shader 却执行了 `discard`，就会在画面上留下错误的隐形遮挡黑洞！
  3. 在 Fragment Shader 中写入 UAV / SSBO 原子缓冲（侧信道副作用）且未显式声明 `layout(early_fragment_tests) in;`。

⚖️ 为什么不透明物体要“从近到远”画，而半透明物体必须“从远到近”画？

  • 阶段一：不透明物体 (Opaque Pass)：开启深度测试 (`DepthTest = LESS`) 且开启深度写入 (`DepthWrite = ON`)，按 从近到远 (Front-to-Back) 排序提交——让近处物体率先填满 Z-Buffer，使后方被挡住的物体全部被 `Early-Z` 零成本剔除！
  • 阶段二：半透明物体 (Transparent Pass)：因为标准 Z-Buffer 每像素只存 1 个深度，无法混合插在中间的玻璃；因此必须保持深度测试开启 (`DepthTest = LESS`)，但关闭深度写入 (`DepthWrite = OFF`)，严格按 从远到近 (Back-to-Front 画家顺序) 依次执行 Alpha Blending：$C_{\text{dst}} \leftarrow \alpha C_{\text{src}} + (1-\alpha) C_{\text{dst}}$！
